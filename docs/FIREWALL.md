# FIREWALL — محافظت کد (FW-01)

سیستم هفت‌لایه محافظت این ریپو — الگو گرفته خط‌به‌خط از پروژه hamneshin. هدف:
**تغییر در یک قسمت هرگز بی‌اجازه به قسمت‌های دیگر آسیب نزند** (کلاس رگرسیون‌های
گذشته: لاگین از کار افتاد، تب‌های سایدبار ناپدید شدند، بازیابی دستی لازم شد).

## دستورها

```
bash fw.sh self-tests    # هر گارد خودش را جعل‌آزمایی می‌کند (اثبات تشخیص)
bash fw.sh guard         # همه گاردها، دقیقاً مثل CI
bash fw.sh verify        # self-tests + guard  ← قبل از هر push
bash fw.sh verify-full   # verify + go test کامل هر ۳ ماژول
bash fw.sh golden-update # بازتولید آگاهانه قراردادهای طلایی (diff را بازبینی کن!)
bash fw.sh commit-lint "origin/main..HEAD"
```

## هفت لایه

| # | لایه | پیاده‌سازی اینجا |
|---|---|---|
| ۱ | معماری به‌عنوان فایروال | سه ماژول Go جدا (go.mod مستقل)؛ مرزهای داخل financial با تست‌های گارد حسابداری |
| ۲ | قراردادهای منجمد | `contracts/golden/`: مسیرهای portal، کلیدهای منو، تب‌های وب مالی |
| ۳ | گاردهای مکانیکی | `scripts/fw/check-*.sh` — هر کدام `--self-test` و قرارداد خروجی `0/1/2` |
| ۴ | لجر append-only | `quality-baseline.d/` — کف‌ها «اندازه‌اند نه آرزو»؛ آخرین ورودی برنده |
| ۵ | متا-گارد | `scripts/fw/check-ci-contract.sh` (R1..R5) — فایروالِ فایروال |
| ۶ | CI و دیپلوی | `.github/workflows/firewall.yml` + ci.yml؛ اکشن‌ها پین به SHA؛ تصاویر بدون `:latest` |
| ۷ | پروسه | `AGENTS.md` — فقط فایل‌های تسک، وابستگی جدید = STOP، evidence-on-done |

## گاردها

| گارد | می‌گیرد چه چیزی را |
|---|---|
| `check-golden-contracts` | ناپدید شدن route/منو/تب (diff با فایل طلایی) |
| `check-migration-safety` | DROP/RENAME/ALTER TYPE بی‌اجازه در SQL |
| `check-secret-defaults` | پسورد/سکرت پیش‌فرض خاموش در کد و deploy |
| `check-compose-no-latest` | تصویر `:latest` در مانیفست‌های دیپلوی |
| `check-gofmt` | فایل‌های Go فرمت‌نشده |
| `check-test-floor` | کوچک شدن بی‌صدا درخت تست (کف لجر) |
| `check-commit-subject` | موضوع کامیت خارج از قرارداد |
| `check-ci-contract` (متا) | حذف/تضعیف هر گارد یا CI، bypass، اکشن پین‌نشده |

## قوانین لجر (quality-baseline.d/)

- **فقط اضافه‌کردن** — ویرایش/حذف ورودی ممنوع حتی برای اصلاح اشتباه؛ ورودی جدید
  بده (`YYYYMMDD-HHMMSSZ-slug.json`)، در هر بخش آخرین ورودی برنده کل بخش است.
- کف/سقف = اندازه هنگام merge؛ بالا بردن نیاز به `note` با دلیل دارد؛ پایین آوردن = رگرسیون.
- «نتوانستیم اندازه بگیریم» (exit 2) شکست است، هرگز skip نیست.

## قراردادهای طلایی

`contracts/golden/*.txt` snapshot ساختاری کد است، نه آرزو. تغییر عمدی =
`bash fw.sh golden-update` → diff طلایی در PR بازبینی می‌شود (diff سطح بازبینی است).
گارد هر مغایرت ناخواسته را قرمز می‌کند — این همان گاردی است که «تب ناپدیدشده» را می‌گیرد.
